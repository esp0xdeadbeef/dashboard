# BUG: `wait_pane_idle` returns a marked launcher-exit value and needs a busy sample; callers that predate both mis-read a long boot as a death

**Filed by:** the HAT (`network-site-esp/scripts/hat-isp.py`), 2026-11-13.
**Affects:** any caller that uses `wait_pane_idle` to wait out a launcher that takes minutes
to produce its prompt.

## What changed recently, and why it matters to a caller

Three of this repository's own fixes changed the contract `wait_pane_idle` offers:

- `1cf9db3` "fix(wait_pane_idle): mark the launcher-exit return" -- the return value is now
  `LAUNCHER_EXIT_PREFIX + <line>` (`main_tdashboard.py:983`, `"launcher exited: "`) rather
  than an ambiguous plain string;
- `d629f63` / `63abf78` -- a busy sample is now required, so the first sample cannot report
  "finished" for a job that has not started;
- `37aa5aa` -- `pane_stream` is the supported long-read path.

All three are right. The problem is the *shape* of the contract for a launcher that takes
20-25 minutes to reach a prompt, which is the normal case for a NixOS VM build on a loaded
machine.

## The symptom, from the HAT side

`hat-isp.py start neon` returned

    guest did not come up; the launcher exited first. Last line: ''
    (an interrupted run reports 'error: interrupted by the user')

while, checked immediately afterwards:

    $ hat-isp.py state neon
    %268 BUSY chain=[zsh > .nixos-shell-wr > .qemu-system-x8]
    guest: present

and the guest then passed `core` and served `ppp0` normally. So the run was healthy and the
verdict was wrong. `_launcher_running(neon)` was `True` and `site_vm_pid(neon)` was a live
QEMU at the moment of the failed report.

Two distinct causes, both contract-shaped rather than logic errors:

1. **The marker is not honoured by callers.** A caller written before `1cf9db3` treats any
   returned string as "the command's output". It cannot tell `"launcher exited: error:
   interrupted by the user"` from `""`, so a run that ended cleanly and a run that died look
   the same. The prefix exists precisely to prevent that; it needs to be exported somewhere a
   caller can import (a `compat` re-export would do), and the docstring should say that
   callers MUST test for it.
2. **A long boot looks like an exit.** During a VM boot the pane's foreground chain is
   `zsh > nixos-shell-wr > qemu-system-x86_64`; QEMU is a *terminal host*, so
   `is_terminal_host` is true and `pane_state(...).ready` is false for the whole boot. If
   `wait_pane_idle` decides "launcher exited" from scrollback rather than from the launcher
   process, it fires during exactly this window -- and a previous run's
   `error: interrupted by the user` is sitting in that scrollback because the pane is reused.

## What the caller already does, and why it is not enough

`hat-isp.py` now asks the machine rather than the pane (`_launcher_running` scans `/proc` for
a `nixos-shell` naming this fixture; `site_vm_pid` does the same for the image). That works,
and it means **the launcher's liveness question belongs to the caller, not to the pane** --
which is worth stating in the docstring, because two callers have now got it wrong
independently.

## What would fix it in this repository

1. Re-export `LAUNCHER_EXIT_PREFIX` from `compat` so callers can test it without importing
   `main_tdashboard`, and say in `wait_pane_idle`'s docstring that the return value must be
   tested for it.
2. Make "launcher exited" **not** reachable while a live terminal host is a descendant of the
   pane -- `termstate` already has `_terminal_host_running` for this -- so a boot cannot be
   reported as an exit by construction rather than by each caller's own guard.
3. Alternatively, return a small structured result (`ok`, `launcher_exited`, `line`) instead
   of a string that carries a prefix. A caller cannot forget to check a field it must name.

## Reproduce

    hat-isp.py start neon      # a VM build that takes >15 min on a loaded machine
    # during the build, with a previous interrupted run's marker in scrollback:
    #   "guest did not come up; the launcher exited first. Last line: ''"
    hat-isp.py state neon      # -> "guest: present"

Nothing is wrong with the site in that window; the build finishes and the guest works.
