# BUG: a non-interactive run exits 0 with no session, and the docs do not say how to drive it unattended

Written 2026-11-12 from a real attempt to use `tmux-dashboard` **unattended**
to drive a long `nixos-rebuild switch` on a remote host (`--target
100.64.0.18:sudo`). The attempt failed, and every step that failed was a
documentation/behaviour gap, not a mistake in the session file alone.

## Severity

HIGH for anyone scripting the dashboard (CI, an agent, a cron-like deploy).
The tool is excellent when attended and interactive; the unattended path is
where these land.

## What was tried

1. Read `README.md` → "Usage" only documents the **interactive** flow
   (`ipython3 main_tdashboard.py -i ...`). There is no "run a session file to
   completion without a REPL" example, so the natural first move was `-i`.
2. `-i` (interactive) fed by a pipe crashed:
   ```
   $ printf 'a\nexit\n' | tmux-dashboard -i --target 100.64.0.18:sudo scripts \
        --session-file ./scripts/smoke.py
   id to spawn or name to spawn: Traceback (most recent call last):
     ...
     id = input('id to spawn or name to spawn: ')
   EOFError: EOF when reading a line
   ```
   The README never says `-i` is *only* for a real TTY.
3. Dropping `-i` (which per `--help` "spawns all sessions") then ran the file
   but reported:
   ```
   $ tmux-dashboard --target 100.64.0.18:sudo scripts --session-file ./scripts/smoke.py
   dashboard: no tmux session named 'smoke'
   dashboard: target 100.64.0.18:sudo via ssh 100.64.0.18 as root  (host s-nodus)
   Trying to get active_pane of smoke
   === EXIT=0 ===
   ```
   **Non-zero exit, but the same message is also what the *shipped* tutorial
   prints on its first run** — so it reads like a failure when it is really the
   normal "not spawned yet" probe. Nothing was left running:
   ```
   $ sudo tmux list-sessions          # on 100.64.0.18
   no server running on /tmp/tmux-0/default
   ```
   (Observed exit codes: `2` when run against a
   `scripts` directory that contains the session file, both locally and via
   `--target 100.64.0.18:sudo`; see "Reproduction". An earlier attempt that
   pointed `scripts` at a directory whose contents differed exited `0` — the
   `scripts` positional is a *directory* of files, and pointing it at the wrong
   directory changes the outcome silently. That is itself worth documenting.)

## Bugs (each independently fixable)

### B1. `no tmux session named '<x>'` is printed for the normal first-run path

In `s_all(respawn_all=False)` the first thing done is
`compat.require_session(server, name)`, which raises and prints
`dashboard: no tmux session named '<name>'` **before** the `spawn_*` function
has had any chance to create it. On a clean target this message is printed on
*every* run and is not an error. It reads as one.

**Fix:** probe with `compat.get_session(...)` and stay silent (or print
`spawning '<name>' (not present yet)`), and reserve `require_session`'s error
for a genuine miss *after* the spawn attempt.

### B2. A pane whose shell exits deletes the session, and the runner does not report it

There is no `remain-on-exit` set anywhere (`rg remain-on-exit` finds nothing).
A `spawn_*` pane that runs `hostname; ...; echo OK` returns to the shell; in a
non-interactive tmux the shell then exits and tmux reaps the session. `main()`
afterwards does:

```python
session = compat.get_session(server, name)
if session is None:
    continue          # <-- silent; no warning, no non-zero exit
```

So the run can "succeed" with nothing durable having been produced, and the
exit code alone is not a reliable signal (observed `2` in the reproduction
below; the silent `continue` would mask it entirely if an earlier session of
the same name survived).

**Fix (pick one, or all):**
- Set `remain-on-exit on` for spawned sessions/windows, so a finished pane is
  inspectable and the session survives for a reader.
- In the non-interactive path, if a session is gone right after `spawn_*`,
  print a clear warning and exit non-zero — "session '<name>' no longer exists;
  a pane's shell likely exited (panes must keep an interactive shell alive or
  set remain-on-exit)".
- Document the invariant explicitly: **a session file must not exit its last
  pane's shell** (the tutorial mentions "do not end with `exit`", but not the
  inverse failure — a *non-interactive* shell that simply returns kills the
  session).

### B3. `-i` under a pipe is a hard `EOFError` crash

`interactive_dashboard()` calls `input(...)` unconditionally. Piping a command
list (the obvious way to script it) crashes instead of either consuming the
pipe or refusing with a clear message.

**Fix:** if `not sys.stdin.isatty()`, either read commands from stdin as a
simple line protocol, or exit with `dashboard: --interactive needs a TTY; drop
-i to spawn all sessions non-interactively`.

### B4. Session naming is derived from the `spawn_<name>` suffix — undocumented

`s_all()` computes `name = session_function.split('_')[-1]`, so `spawn_smoke`
→ session `smoke`. A session file whose function is `spawn_test` but which
calls `renew_session("smoke")` fails with B1's message and never recovers,
because the runner looks for session `test`. This is easy to get wrong and the
README does not state the rule.

**Fix:** document "the session name is the `spawn_` suffix; `renew_session`
must use the same name", and/or assert in `s_all` that the session created by
`spawn_<name>()` is actually named `<name>`, with a message naming the mismatch.

### B5. Usage examples do not show `scripts` as a positional together with `--target`

```
$ tmux-dashboard local scripts --session-file ./scripts/smoke.py
main_tdashboard.py: error: unrecognized arguments: scripts
```
Because `local` is consumed as... nothing useful here — a reader naturally
writes the target as a second positional. The correct form is
`--target local scripts --session-file ...`. The README's "Targets" section
shows `--target l-portal scripts ...` but not the failure mode, and `--help`
does not say `scripts` is positional and must follow the flags.

**Fix:** add a copy-pasteable non-interactive example and a one-line note that
`scripts` is a positional argument (put it after `--target …`).

### B6. `scripts` is a directory of files, not the session file

The positional `scripts` is a *directory* (`get_dir_session_files(args.scripts)`
lists it); the session file is passed separately via `--session-file`. Pointing
`scripts` at a directory whose contents differ from where the session file
lives silently changes the run's outcome (it even flipped exit code `0` vs `2`
in testing), and there is no check that the two are consistent.

**Fix:** document that `scripts` is a directory, and warn when
`--session-file`'s directory differs from `scripts` (or when `scripts` does not
contain the session file), since that is almost always an operator mistake.

## What the docs should gain (beyond the fixes above)

A short section, "Running a session file unattended", covering:

- drop `-i` to spawn every `spawn_*` and exit (this is the scripted path);
- `-i` needs a TTY — do not pipe into it;
- the `spawn_<name>` → session-name rule (B4);
- panes must keep an interactive shell alive, or set `remain-on-exit`, or the
  session disappears and the run still exits 0 (B2);
- the `no tmux session named …` line is expected on first run (B1 → silent
  after fix);
- the real exit status of a long command is only visible if the session file
  records it (e.g. `echo EXIT=${PIPESTATUS[0]}`) into a pane you then capture
  with `pane_stream`/`pane_capture` — the runner does not surface it.

## Reproduction

```bash
# on any host with tmux; note exit 0 and then no session
cat > /tmp/smoke.py <<'PY'
def spawn_smoke():
    s = renew_session("smoke")
    w = compat.windows_of_session(s.session_name)[0][0]
    p = compat.active_pane_of_window(compat.window_by_id(w))
    compat.send_keys(p, "hostname; echo SMOKE_OK")
    compat.send_keys(p, "C-m")
PY
tmux-dashboard --target local /tmp/scripts --session-file /tmp/smoke.py ; echo "exit=$?"
# printed:  dashboard: no tmux session named 'smoke'
#           Trying to get active_pane of smoke
#           exit=2
tmux list-sessions   # -> no 'smoke' session survives (B2)
```

## Do not

Do not "fix" this by making the runner block forever or by attaching a TTY
requirement to the non-interactive path; the point of the non-interactive path
is to spawn and return. The fixes above keep that contract and only make the
silent-success case loud, plus document the invariants.
