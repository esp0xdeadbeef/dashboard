# BUG: `wait_pane_idle` still returns the prompt, not the command's output

**Severity:** MEDIUM — callers treat the return value as quotable evidence; it is
the prompt or the typed command.
**File:** `main_tdashboard.py` (`wait_pane_idle`, lines ~988-996)
**Status:** OPEN — regression of the return-value half of
`BUG-f03d05d8-a7db-48ad-9efe-f088d2f83848`

## Context

`BUG-f03d05d8-…` reported two things: `wait_pane_idle` returned the prompt (or
the typed command) instead of the command's output, and it could return before
the command had started. `63abf78` fixed the second one (an idle sample is now
accepted only after the pane has been seen busy, with a 2s grace) and stated
"every point in it is addressed". The first point is not: the return expression
is unchanged.

```python
# main_tdashboard.py, wait_pane_idle, both return sites (around 991 and 995)
return tail[-1].rstrip() if tail else ""
```

`tail` is the last 12 non-empty captured lines taken *after* the pane reached a
prompt, so `tail[-1]` is the prompt the shell printed on its way back — the
command's output is always above it.

## Exact reproduction (unchanged from the original report)

```
$ cd ~/github/dashboard && source venv/bin/activate
$ python3 - <<'PY'
import libtmux, main_tdashboard as md
tmux = libtmux.Server()
s = tmux.new_session(session_name="recheck", window_name="w", attach=False)
pane = s.windows[0].panes[0]
pane.send_keys("printf 'OUTPUT_MARKER_42\\n'")
r = md.wait_pane_idle(pane, timeout=10)
print("returned:", repr(r))
print("contains output marker?", "OUTPUT_MARKER_42" in str(r))
s.kill()
PY
returned: '└─[%]'
contains output marker? False
```

Run after `63abf78`; the command had clearly completed (the prompt had returned
and the marker was on screen one line above).

## Why it matters

The docstring still promises:

> Returns the last non-empty screen line so the caller can quote what it saw

So the documented, obvious caller is `evidence = wait_pane_idle(pane)`, and that
records a prompt. It cannot distinguish "the command printed nothing" from "the
command printed something", which is the exact confusion the docstring says the
function exists to prevent.

## Suggested fix (pick one, then make the docstring true)

1. Return the output: take the captured lines between the echoed command and the
   returning prompt, and return those (empty string when the command printed
   nothing). This makes the existing docstring correct.
2. Keep returning the prompt line but rename/redocument the function to say so,
   and add `wait_pane_output(pane, timeout=...)` for the result, so callers stop
   treating a prompt as evidence.

Whichever is chosen, please add a case to `test_detection.py` (or a sibling
`test_*` module listed in `flake.nix`'s `ci` derivation) that runs a command
printing a marker and asserts the marker is in the returned value — the current
`WaitPaneIdle` cases check ordering, not content, which is why this survived the
first fix.
