# BUG: `wait_pane_idle` returns the prompt, not the command's output

**Severity:** MEDIUM — the documented return value is a result the caller can
quote; in practice it is the shell prompt or the typed command, so a caller that
reports "what the pane said" reports the wrong thing.
**File:** `main_tdashboard.py` (`wait_pane_idle`, `at_end`)
**Status:** OPEN

## Symptom

`wait_pane_idle`'s docstring says:

> Returns the last non-empty screen line so the caller can quote what it saw

That line is captured at end-of-command, when the pane is back at a prompt, so
the "last non-empty line" is normally the prompt (or, on a fast command, the
echo of the command itself). The command's actual output is never returned.

## Exact reproduction

```
$ cd ~/github/dashboard && source venv/bin/activate
$ python3 - <<'PY'
import libtmux, main_tdashboard as md
tmux = libtmux.Server()
s = tmux.new_session(session_name="staler2", window_name="w", attach=False)
pane = s.windows[0].panes[0]
pane.send_keys("printf 'OUTPUT_MARKER_42\\n'")
r = md.wait_pane_idle(pane, timeout=8)
print("returned:", repr(r))
print("contains output marker?", "OUTPUT_MARKER_42" in str(r))
print("screen tail:", [l for l in pane.capture_pane(start="-10") if l.strip()][-2:])
s.kill()
PY
returned: '└─[%]'
contains output marker? False
screen tail: ['3 00:11]', '└─[%]']
```

And with a cleared screen the return is the typed command itself:

```
$ python3 - <<'PY'
import libtmux, main_tdashboard as md
tmux = libtmux.Server()
s = tmux.new_session(session_name="staler", window_name="w", attach=False)
pane = s.windows[0].panes[0]
pane.send_keys("clear; echo '=== step1'; true")
print("returned:", repr(md.wait_pane_idle(pane, timeout=8)))
s.kill()
PY
returned: "clear; echo '=== step1'; true"
```

## Why it matters

This is the call an unattended run makes to collect a result — for example a
CI-watch pane whose command has finished. The contract says the return value is
quotable evidence, so a caller writes `evidence = wait_pane_idle(pane)` and
records a prompt. That is indistinguishable from "the command produced nothing",
which is the failure mode the docstring was written to prevent (it cites a
`systemctl restart pppd` run that "returned immediately with no output at all").

It also explains a related symptom seen while watching a long `gh run watch`:
the pane reports idle with a blank or prompt-only tail while the run is still
in progress, because the *foreground* process the wait keys on can be the shell
between refresh cycles.

## Expected

Either:

- return the command's output — the lines between the typed command and the
  returning prompt — so the value matches the docstring; or
- change the docstring to say it returns the *prompt line* and add a separate
  accessor for captured output, so callers stop treating it as a result.

Whichever is chosen, a caller should be able to tell "the command printed
nothing" from "the command printed something" without capturing the pane
itself.

## Verified on

Linux, `tmux 3.7b`, `venv/bin/python` 3.13, dashboard checkout at
`~/github/dashboard` (cade39b). Both reproductions above were run as written.
