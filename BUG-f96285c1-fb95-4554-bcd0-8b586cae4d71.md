# Audit: is the "returns chrome instead of output" bug common across repositories?

**Asked:** whether the `wait_pane_idle` defect (returning the prompt instead of
the command's output) is common in the other repositories.
**Answer:** no — it was one defect in one function. But the audit found two
*consequences* that outlived it, below.
**Status:** OPEN (two stale-contract call sites)

## Method

Searched every checkout under `~/github` for pane automation, both Python and
shell:

```

$ grep -rln "wait_pane_idle\|pane_capture\|capture_pane" --include="*.py" . | grep -v /venv/
```

No `network-*` repository reimplements tmux pane automation; the dashboard is
the single owner. The shell uses of `tmux capture-pane` in

```
# this run's exit and `wait_pane_idle` returns immediately with a dead verdict --
```

So one consumer had already worked around it rather than the bug being copied.

## Verified fixed in the shared primitive

Against current `main_tdashboard.py` (with the in-tree fix applied):

```
$ python3 - <<'PY'
import libtmux, main_tdashboard as md
s = libtmux.Server().new_session(session_name="c", window_name="w", attach=False)
pane = s.windows[0].panes[0]
pane.send_keys("printf 'MARKER_COMMON_7\\n'")
print(repr(md.wait_pane_idle(pane, timeout=10)))
s.kill()
PY
'MARKER_COMMON_7'
```

and a command that prints nothing returns `''`, not the prompt.

## Finding 1 — a second return path still returns the prompt

`wait_pane_idle` has two return sites. The normal path now returns the command's
output through `_pane_output(pane, baseline)`. The `launcher_exited` path still
does:

```python
        if termstate.launcher_exited(target):
            tail = [ln for ln in compat.capture_pane(pane, start="-24")
                    if ln.strip()]
            return tail[-1].rstrip() if tail else ""
```

Here the last screen line *is* the intended value — `termstate.launcher_exited`
returns the launcher's error line so the caller can quote it (a crashed
`nixos-shell`) — so the behaviour is right, but the docstring now describes only
the output contract. A caller cannot tell which of the two shapes it received
without a sentinel. **Suggested:** return a small result object, or prefix the
launcher case with a documented marker, and say so in the docstring.

## Finding 2 — callers and comments still encode the old contract

These are live, in this repository, and were written against "returns the last
non-empty screen line":

- `scripts/ncpm_suite.py:40` — `# wait_pane_idle returns the last non-empty
  line, so finish with the status in a form that reads back unambiguously`, and
  the command it builds appends `echo SUITE_EXIT=$?` purely to make that last
  line readable. Under the new contract the return value is the whole output
  block:

  ```
  $ pane.send_keys("echo one; echo two; echo SUITE_EXIT=0"); wait_pane_idle(...)
  returned: 'one\ntwo\nSUITE_EXIT=0'
  ```

  The `SUITE_EXIT=` sentinel is now redundant for parsing, and the comment is
  false. Harmless here (the value is printed, not parsed), but it teaches the
  old contract to the next reader.

- `scripts/ci_wait_session.py:5-8` — explains that it uses `checked_cmd`
  because "`wait_pane_idle` alone returns on the first idle sample". That was
  fixed in 63abf78 (a busy sample is now required, with a 2s grace), so the
  rationale is stale even though using `checked_cmd` remains a good choice.

## Recommendation

One fix in the primitive, two one-line comment updates, and a regression test
that asserts (a) output is returned, (b) an empty print returns `''`, and (c)
the launcher-exit path is distinguishable from output. The existing
`WaitPaneIdle` cases check ordering, not content, which is why the original
defect survived its first "fix".
