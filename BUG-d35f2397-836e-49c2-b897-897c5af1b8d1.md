# BUG: `_pane_output` silently drops real output that looks like prompt chrome

**Severity:** HIGH — a command's own output is discarded and the caller is told
the command printed nothing. No error, no marker, no way to notice.
**File:** `main_tdashboard.py` (`_pane_output`, `is_chrome` / `is_echo`)
**Status:** OPEN

## Context

`4c2d3e0` replaced the impossible `baseline` diff with an anchor on the echoed
command line, which fixed the stale-output defect reported in
`BUG-959b4fd7-2df9-4e4d-b3a9-4578b2fa254e` — verified working:

```
1 marker-only     : 'MARK_RETEST'
2 silent after    : ''
3 sequential      : 'FIRST_OUTPUT' 'SECOND_OUTPUT'
4 silent again    : ''
5 multi-line      : 'one\ntwo'
```

The new filter is too eager, though. To strip the prompt it drops **every** line
that starts with a box-drawing character (`is_chrome`) — and box-drawing
characters are exactly how `tree`, `ls --tree`, `nft list ruleset`,
`systemctl --no-pager` and any table with `│` separators render their output.

## Exact reproduction

```
$ cd ~/github/dashboard && source venv/bin/activate
$ python3 - <<'PY'
import libtmux, main_tdashboard as md
tmux = libtmux.Server()
s = tmux.new_session(session_name="chrome3", window_name="w", attach=False)
p = s.windows[0].panes[0]
def w(cmd):
    p.send_keys(cmd); return md.wait_pane_idle(p, timeout=10)
print("ls --tree style :", repr(w("printf 'a\\n├── b\\n└── c\\n'")))
print("only box lines  :", repr(w("printf '├── b\\n└── c\\n'")))
print("pipe-prefixed   :", repr(w("printf '│ col1 │ col2 │\\n'")))
s.kill()
PY
ls --tree style : 'a'
only box lines  : ''
pipe-prefixed   : ''
```

`printf 'a\n├── b\n└── c\n'` prints three lines and returns `'a'`: two are
silently discarded. A command whose entire output is box-drawn returns `''` —
indistinguishable from a command that printed nothing.

The screen really does contain the dropped lines:

```
$ python3 - <<'PY'
... p.send_keys("echo '└─[%] fake prompt'"); print(repr(md.wait_pane_idle(p, timeout=10)))
... print([l for l in p.capture_pane(start="-6") if l.strip()])
PY
returned: ''
screen tail: ["printf 'LINE_A\\n'", '┌─[deadbeef@l-esp:laptop] - [...]',
              '7]', "└─[%] printf 'LINE_A\\n'", 'LINE_A', ...,
              "└─[%] echo '└─[%] fake prompt'", '└─[%] fake prompt', ...]
```

## Scope of the loss

The filter applies to **every** line of the body, not just the leading chrome, so
a mixed block is partially returned:

```
mixed, chrome first : 'plain'        # from printf '├── a\nplain\n└── b\n'
mixed, plain first  : 'plain'        # from printf 'plain\n├── a\n'
indented tree       : ''             # from printf '  ├── nested\n'
```

That last one matters for real tooling: `tree`, `ls --tree`, `nft`, `systemctl
--no-pager` and `docker ps`-style tables all emit `├──`, `└──` or `│`. An agent
probing such a command through this helper records "no output" for a command
that produced a full listing — the exact silent-success shape the earlier fixes
in this series existed to remove.

## Suggested fix

Discriminate on **position and context**, not on the character alone:

- strip chrome only from the tail after the last echoed command line (already
  the `start_idx` anchor), and only while it matches the prompt shape the pane
  actually shows — the prompt line is `<box chrome><sigil><command>`, so test
  the whole line against the prompt table (`prompts.match_line`), not its first
  character;
- never drop a line because it begins with `├`, `└`, `│` or `─` when the line
  does not also match a prompt;
- if the body would become empty while the screen after the echo is non-empty,
  return the non-empty lines rather than `''` — preferring visible output over a
  suspected-prompt verdict is the safer failure.

Regression cases worth adding (none of the current `WaitPaneIdle` cases would
catch this, they stand in a mock bare-prompt screen):

1. `printf 'a\n├── b\n└── c\n'` returns all three lines;
2. `printf '│ c1 │ c2 │\n'` returns that line;
3. a genuinely silent command still returns `''`;
4. a sequential pair still returns `''` then the new output (the `4c2d3e0` fix
   must not regress).
